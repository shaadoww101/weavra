# Weavra — Deployable version

A truly working public version of Weavra, the AI work exchange — with a backend, not a static demo.

- **Discover landing** (hero, platform, marketplace, builders, use cases, pricing, FAQ) in the original dark `#080d13` / lime `#c8f169` / Manrope design
- **All 6 agents testable**: Atlas, Quill, Relay, Nova, Signal, Pulse — with profile modals and a visible Knowledge Base panel
- **Grounded chat**: keyword RAG over the knowledge base, answers cite their sources, and unsupported questions abstain with “not covered in the knowledge base”
- **Workflow builder**: name a workflow, start from templates or blank, add/remove steps, assign any agent per step, add human approval gates, run it live with a step-by-step log
- **Waitlist / builder signup** that actually saves (JSON-file persistence)
- **Provider-agnostic LLM layer, OpenAI by default**: OpenAI (`gpt-4o-mini`) is the primary provider; Anthropic and Cohere are supported as fallbacks via env vars

## Demo mode vs live mode

| | Demo mode | Live mode |
|---|---|---|
| When | No LLM key set | `LLM_PROVIDER=openai` + `OPENAI_API_KEY` set (or another provider + its key) |
| Chat | Answers built from the seeded knowledge base, labelled **DEMO MODE** in the UI and in API responses (`"mode": "demo"`) | Answers generated by the LLM, grounded in retrieved knowledge, `"mode": "live"` |
| Honesty | Never pretends to be live AI | Falls back to a labelled demo answer if the LLM call fails |

The top badge in the UI shows the current mode. There is no fake “live” state.

## Quick start (local)

```bash
npm install
npm start
# open http://localhost:3000
```

Requires Node 20+. No native-build dependencies, no database server — data lives in `data/db.json`, seeded on first run (6 agents, 15 knowledge docs, 3 workflows).

## Docker

```bash
docker compose up --build
# open http://localhost:3000
```

Or plain Docker:

```bash
docker build -t weavra .
docker run -p 3000:3000 -v weavra-data:/app/data weavra
```

## Deploy on Render

1. Push this folder to a Git repo (GitHub/GitLab).
2. In Render: **New → Web Service → Build and deploy from a Git repository**, pick the repo. Render detects `render.yaml` (Node, free plan, `npm ci` build, `node server.js` start, 1 GB persistent disk mounted at the data folder).
3. Or use the Blueprint: **New → Blueprint**, point at the repo.
4. Set env vars in the Render dashboard (never in code):
   - `LLM_PROVIDER=openai`
   - `OPENAI_API_KEY=…` (your OpenAI key — set as a secret env var in Render)
   - To use a fallback instead, set `LLM_PROVIDER=anthropic` + `ANTHROPIC_API_KEY`, or `LLM_PROVIDER=cohere` + `COHERE_API_KEY`.
5. Deploy. Health check: `https://<your-service>.onrender.com/api/health`

> Note: on Render's free plan the service sleeps after inactivity, so the first request after a pause can take ~30–60s.

## LLM configuration (OpenAI is the primary path)

The server defaults to `LLM_PROVIDER=openai` with model `gpt-4o-mini`. With no key set it runs in demo mode; set `OPENAI_API_KEY` to go live. Anthropic and Cohere remain supported as fallbacks — set `LLM_PROVIDER` to `anthropic` or `cohere` plus that provider's key.

```bash
cp .env.example .env   # then edit .env — never commit it
```

| Variable | Meaning |
|---|---|
| `LLM_PROVIDER` | `openai` (default / primary) \| `anthropic` \| `cohere` |
| `OPENAI_API_KEY` | OpenAI key — the primary key. Set this to go live on OpenAI. |
| `LLM_MODEL` | Optional model override (takes precedence over the per-provider vars below) |
| `OPENAI_MODEL` | Optional OpenAI model override (default `gpt-4o-mini`) |
| `ANTHROPIC_API_KEY` | Anthropic key (only if `LLM_PROVIDER=anthropic`) |
| `ANTHROPIC_MODEL` | Optional Anthropic model override (default `claude-sonnet-4-20250514`) |
| `COHERE_API_KEY` | Cohere key (only if `LLM_PROVIDER=cohere`) |
| `COHERE_MODEL` | Optional Cohere model override (default `command-a-03-2025`) |
| `PORT` | Server port (default `3000`; Render sets this automatically) |
| `DATA_FILE` | JSON database path (default `./data/db.json`) |

### Costs (rough, check the provider's current pricing)

- **Demo mode: $0** — no LLM calls at all.
- **OpenAI `gpt-4o-mini`**: a few cents per 1,000 short chats; a small public demo typically costs well under $5/month at low volume.
- **Anthropic Claude Sonnet / Cohere Command-A**: more per token than `gpt-4o-mini`; still cents per chat at this size.
- **Hosting**: Render free plan $0 (sleeps when idle); Docker on a small VPS ~$4–6/month. The JSON database needs no paid database.

Set a usage limit / spend cap in your LLM provider dashboard before sharing the link publicly.

## API

| Method & path | Description |
|---|---|
| `GET /api/health` | `{ ok, mode, provider, agents, knowledge, workflows, waitlist }` |
| `GET /api/mode` | `{ mode: "live" \| "demo", provider, live }` |
| `GET /api/agents` | All 6 agents |
| `GET /api/knowledge` | All knowledge docs |
| `POST /api/knowledge` | `{ title, collection, content }` → creates a doc |
| `POST /api/chat` | `{ agent, message }` → `{ answer, citations[], mode, agent }` |
| `GET /api/workflows` | All workflows |
| `POST /api/workflows` | `{ name, steps: [{ type, title, desc, agent }] }` → creates a workflow |
| `POST /api/workflows/:id/run` | Runs steps in order; pauses at Approval steps (`status: "waiting_approval"`) |
| `POST /api/workflows/:id/approve` | `{ runId }` (or latest waiting run) — resumes past the approval gate |
| `GET /api/workflows/:id/runs` | Runs for a workflow |
| `GET /api/runs/:id` | One run with its log and results |
| `POST /api/waitlist` | `{ name, email, type }` → saves a signup |
| `GET /api/waitlist` | All signups |

Step types: `Trigger`, `Knowledge`, `Agent`, `Approval`, `Output`.

## Seeded data

- **Agents** (verbatim from the original designs): Atlas, Quill, Relay, Nova, Signal, Pulse.
- **Knowledge**: 15 docs — Company handbook (refund policy), Product documentation (workspaces), Sales playbook (qualification), plus 2 per agent (Atlas research, Quill content, Relay operations, Nova development, Signal data, Pulse growth).

Data is stored in `data/db.json`. Delete that file to re-seed from scratch. It is git-ignored; in Docker/Render it lives on the persistent volume/disk.

## Security notes

- API keys live only in env vars / the hosting dashboard, never in code, files, or logs.
- This is a demo-grade deployment: there is no auth on the API, so anyone with the URL can add knowledge, run workflows, and (in live mode) spend your LLM credits. Add auth / rate limiting before using it for anything beyond a public demo.
- Validate `LLM_PROVIDER` before going live, and set a provider spend cap.
